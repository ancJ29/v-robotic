# P5 report: Strapi locally, and the site reading it

Plain words. Each item ends in one question you can answer yes or no. Nothing here has been pushed.

## What was done

1. Strapi 5.61 runs on this Mac (port 1337) from the content types P1 committed. It started in about 4 seconds from an empty database.
2. The Vietnamese seed (7 product lines, 20 products, 4 industries, 3 showrooms, the site settings) was put into Strapi by a script. Running the script a second time changed nothing and made no duplicates (still 20 products).
3. The site can now read its content from Strapi. A switch decides: by default it reads the seed files, exactly as before, so the live deploy is untouched.
4. Proof: the content read back from Strapi equals the seed, field for field, for all 5 types. And the two sites built from either source are byte-for-byte identical.

## Questions

1. **Is the switch's default right: the site builds from the seed files unless someone sets `CONTENT_SOURCE=strapi`?** Yes keeps the live deploy independent of the server until P6 and P7 flip it in their own workflow; no means the deploy waits on a Strapi box that does not exist yet.
2. **When Strapi is asked for and cannot be reached, is a failed build (rather than a quiet fallback to the seed) what you want?** Yes: nobody ever publishes stale content unknowingly; no: the site would build from the seed instead and say nothing.
3. **English pages will live under `/en/` but keep the Vietnamese page names (for example `/en/san-pham`). Is that acceptable?** Yes: one set of pages, cheap to build in P8; no: P8 must also build translated page names, which is more work, and you would need to supply the English wording.
4. **Products appear in the order they were first created. Is that fine for now?** Yes: nothing to do. No: a "display order" field must be added to products so the client can reorder them (a small P1-style change).
5. **The local admin is `admin@vrobotic.test` with a throwaway password written in `docs/conventions/strapi-local.md`. Is it fine that these dummy values sit in the repository notes?** Yes: they open only a database that lives on this Mac and is deleted on each fresh run; no: I will move them to an uncommitted note.
