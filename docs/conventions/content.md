# Content contract conventions (piece P1)

Decisions a later session should not re-derive. Each is reversible except where it says otherwise.

- **Three places hold the contract, kept equal by a script.** `cms/src/api/*/content-types/*/schema.json` and `cms/src/components/**` (Strapi), `web/src/content/types.ts` (what templates read), `content/seed/<locale>/*.json` (the data). `pnpm --filter content check` (also in root `pnpm check`) fails on any field name, type, enum, required field or relation that differs between them. Change all three in one commit.
- **Seed layout:** `content/seed/vi/<plural>.json`, one file per type (array for collections, one object for `site-settings`). Locale folders because each Strapi locale is a full entry; `en` (P8) is a second folder with the same slugs. `content/` is a workspace package so the check runs under `pnpm -r check`; it has no dependencies.
- **Seed record shape = `types.ts` shape = the schema's own fields.** Relations are slugs (owning side only; `line`, `industries`, `related`, `compatible_with`); inverse sides (a line's products, an industry's products) are derived and never in the seed. Media is `{src, alt, width, height}` or `null`; seed uses none. Empty is `null` or `[]`, never absent.
- **P5's adapter (built; `web/src/content/strapi.ts`, proved equal to the seed in `strapi-local.md`)** turns Strapi's REST answer (`populate` for relations, media, components) into these shapes: relation objects to slugs, media to `MediaRef`, for the request's locale.
- **Field names are snake_case** (as the architecture memo draws them); Strapi's own fields (`documentId`, `publishedAt`) stay camelCase.
- **Localized:** every customer-facing text field, `model` and component text included. Shared: slugs, `order`, enums, booleans, phone/zalo/whatsapp/email, media, `value_number`, `unit`, spec `key`. Default locale is `vi`: `STRAPI_PLUGIN_I18N_INIT_LOCALE_CODE=vi` in `.env` (first run only; in `.env.example`).
- **Slugs are the contract.** A ledger, `content/slugs.json`, lists every slug ever issued; the check fails if one disappears from the seed or one appears that the ledger lacks. Renaming is a deliberate edit of the ledger plus a redirect in the site. Slug is a Strapi `uid`, not localized.
- **Specs:** repeatable component `catalog.spec` with a stable machine `key` (`payload_kg`), display `label`/`value`, numeric `value_number` and `unit`. Filters and comparison join on `key`. Keys unique per product (checked).
- **Soft rules the check enforces and Strapi cannot:** a robot has a `line`, other kinds do not; a product does not list itself in `related` / `compatible_with`.
- **Draft/publish on every type**, so a publish can trigger the rebuild webhook (P6).
- **`lead` is not a Strapi type here.** The memo draws it, but P3 owns its shape (`packages/lead-schema`) and the Worker writes it to R2 first; the Strapi collection arrives with the Phase 2 relay, built from that schema, carrying `schema_version`.
- **Added to the memo's ER:** `slug` on showroom (the lead refers to `showroom_slug`), `order` on industry (twelve of them need a listing order), `key` and `value_number` on spec, `gallery`/`documents` multi-media on product, `slug` pattern and spec-key regex.
- **Seed volume:** 7 lines, 14 robots (one with a full spec sheet, the rest `spec_pending`), 3 accessories, 3 software, 11 industries with 4 journey steps each, 5 showrooms (none confirmed), all text invented; see P1b below, site settings mostly empty. All names say "tạm" (temporary) and carry `name_provisional`.
- **Strapi build quirk:** `cms/tsconfig.json` includes `src/**/*.json`; without it `dist/` has no schemas and Strapi sees none. After editing a schema: `strapi build`, then `strapi ts:generate-types`, and commit the generated files. The first build prints type errors (generated types lack the new types); it still emits, and the second step fixes them.
- **Sandbox:** every `strapi` command prints `EPERM mkdir ~/Library/Preferences/com.strapi` (Strapi's own config folder); harmless, commands go on.
- **Showroom `details_confirmed`** (was `published`, renamed after P1 review): boolean, default false, not localized. False means the page hides the address and hours block; it is independent of Strapi draft/publish, so a showroom can be live with its details unverified.

## P1b: the seed at the screens' size, filled with sample content (2026-11-09)

Counts: industries 4 to 11, showrooms 3 to 5, built pages 36 to 43 (7 net new industry pages; showrooms have no page of their own). Product lines (7), products (14 robots, 3 accessories, 3 software) are unchanged in number; all now carry full text and specifications.

- **Marking convention (changed during the piece: the marker leaves the visible text).** Each record of the four seed types (`product`, `product-line`, `industry`, `showroom`) has a boolean `sample_data`. `true` means: everything in the record except a name read off a client screen is invented. `grep -rn '"sample_data": true' content/seed` lists every sample record in one command. Reason: a boolean sibling field is checked by the validator and the three-way schema check, it travels through Strapi and the adapter, and nothing is printed on the page. In `web/src/copy/*.ts` (not records) the marker is the header comment `SAMPLE-DATA` in each file; there only the first sentence of each string came from a screen.
- **The visible side is one ribbon.** `SAMPLE_CONTENT` in `web/src/lib/site.ts` draws a red ribbon on every page (text in `vi.json`, `site.sampleRibbon`). Set it to false at launch, with the sample data replaced (open item on it).
- **Contract change:** `showroom` gained a localized `description` text (the page prints it under the name). `sample_data` is added to the four schemas, `types.ts`, the adapter and Strapi's generated types. `cms/types/generated/contentTypes.d.ts` was edited by hand to match, not regenerated: run `strapi build` then `strapi ts:generate-types` when Strapi next runs.
- **Real names (from the screens):** industries (screen 03, all 11 legible): Ngân hàng, Showroom, Hành chính công, Trường học, Bệnh viện / Phòng khám, Nhà hàng, Khách sạn, Siêu thị / TTTM, Nhà máy / Kho xưởng, Trại dưỡng lão, Tư vấn tâm lý. Showroom cities (screen 07, all 5 legible): Hà Nội, Đà Nẵng, Nha Trang, TP. Hồ Chí Minh, Cần Thơ. From screen 01: the seven line names and first models V-AURA 01, V-SERVE 01, V-CLEAN 01, V-CARGO 01, V-NAVI 01, V-FORGE 01, V-EMPA 01 (the screen itself calls them provisional). From screen 06: Agent lễ tân, Agent tư vấn, Quản trị tác vụ. The second model of each line (`... 02`), the accessories and everything below is invented.
- **Invented:** every description, summary, tagline, problem text, journey step, specification value (consistent keys within a line, ranges that fit the kind: a 3 kg cobot, a 25 kg palletiser, AMRs at 500 and 1 000 kg), showroom description, the sentences added after the first one in `copy/`. No images. No street address and no opening hours anywhere: every showroom has `details_confirmed` false, address and hours null. (The old open sample showroom's placeholder address was removed, so the seed no longer exercises the confirmed-showroom path; the site's tests do.)
- **Slugs:** old sample slugs kept (`nganh-tam-y-te` is now Bệnh viện / Phòng khám, `nganh-tam-khach-san` Khách sạn, `nganh-tam-san-xuat` Nhà máy / Kho xưởng); new ones are plain (`nganh-ngan-hang`, `showroom-nha-trang`, ...). `nganh-tam-kho-van` was retired on purpose (edited out of the ledger; nothing live, no redirect). Its 7 product links were re-spread: the factory and warehouse products now point at Nhà máy / Kho xưởng, the medical ones at Bệnh viện / Phòng khám.
- **Industry-to-product links:** every one of the 11 industries now has at least two products (Nhà máy / Kho xưởng 7, Bệnh viện 5, Siêu thị 4, the rest 2 to 3), so no industry page hides its products band.
