# The remaining pages (piece P2b)

Decisions a later session should not re-derive. Each is reversible. The shell's own decisions are in `site-shell.md`.

- **Section band: `Band.astro`, the unit P2c builds the homepage from.** Parameters: `tone` (`light`, `panel`, `dark`), `size` (`section`, `hero`), `kicker`, `title`, `subtitle`, `level` (1 makes the title the page's h1), `id`, `label` (aria name when there is no title). Slots: default (content), `aside` (a visual beside the heading), `actions` (buttons under the heading). Heading parts print only when given. Pages never write their own section wrapper.
- **Light page openers keep `PageHead`; dark openers (services, AI, partnership, industry detail) are a `Band` with `tone="dark" size="hero" level={1}`.** The screens show both kinds; reusing `PageHead` keeps the light ones identical to the catalog's.
- **Industry card: `IndustryCard.astro`, one component for the listing only.** Picture left, name, "Khám phá". It takes an `Industry` and builds its own link. The tagline is not on the card because screen 03 shows none.
- **Other small components, each used by two or more pages:** `Callout` (the pale notice bar closing most screens, optional button slot), `InfoCard` (bordered card of screens 05, 06, 08; number badge, subtitle, body, link all optional), `ImageWell` (picture or neutral well, never a broken image), `Markdown` (see below). Everything else is page markup: the about page's numbered list, the journey steps, the contact panel, the showroom tabs.
- **Markdown in the industry problem statement: `lib/markdown.ts`, headings, paragraphs, bullet lists, bold, italic, rendered as text nodes.** The seed's problem statements use `##` and `**`, which the product parser does not handle. `##` renders as h3 and `###` as h4, because the band's title is the h2. No raw HTML, so CMS text cannot inject markup. `lib/text.ts` is untouched.
- **Industry detail follows screen 04 plus one addition.** Dark hero (kicker "Giải pháp ngành X", title is the tagline, or the name when there is no tagline), problem statement, journey, closing notice with a button. The journey is every step in the data, sorted by `order`, in a grid that wraps; nothing assumes three or four. Added: a "products that fit" band built from the products whose `industries` include this one, omitted when there are none. The hero image shows only when the industry has one.
- **Page prose for the five pages with no content type lives in `web/src/copy/<page>.ts`,** one typed object per page shaped like a Strapi single type (fields, and lists as repeatable components), with a `README.md`. This diverges from the plan row ("`content/*.json`"): the seed validator checks every JSON file against a Strapi schema, so JSON with no schema would fail it, and a TypeScript object costs nothing to lift. Shared labels (buttons, kickers, status words) are in `vi.json`, never in `copy/`. Contact facts are not in `copy/`; they come from `site_settings`.
- **Text read off the screens, with one liberty:** screen 13 prints a real phone number and screen 09 a logo; neither is written anywhere in the repository. The screens' empty-box icon glyphs are not built (same as P2a). The illegible parts were none; the "03/13" counters are not built.
- **Showroom page: tabs per city, every panel in the HTML, a small script switches them.** The first open showroom is the one shown first. Without JS only that panel shows, the others are `hidden`. Status words: open "ĐÃ HOÀN THÀNH*", fitting out "ĐANG HOÀN THIỆN*", planned "DỰ KIẾN*", with the screen's asterisk footnote.
- **Unconfirmed showroom: the address-and-hours block is not in the markup at all** (the `<aside class="visit">` is only rendered when `details_confirmed` and there is an address or hours). The card shows the screen's "waiting for the project owner" sentence in its place. Confirmed but with both fields empty also renders no block.
- **The screen-07 booking panel is not built.** It is the booking form (screen 11, P3). The card's red button links to `/showroom/dat-lich`.
- **Contact page: the page, and a marked slot.** The slot is `<div data-form-slot="b2b-contact">` inside a card headed "Thông tin liên hệ", with a comment above it saying exactly what P3 replaces (screen 13's fields, lead kind `b2b_contact`, Turnstile, the Worker). Until then it prints a one-line "form in progress" note. With every one empty it prints the screen's own sentence that these are added after verification. No label, dash or empty row appears for a missing fact.

- **Showroom field renamed `status` to `opening_status`** (values `open`, `fitting_out`, `planned` unchanged).
